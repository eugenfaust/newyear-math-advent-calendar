# 02. Пользователи и авторизация

**Зависит от:** 01.

## Сделать

- Реализовать `User`: UUID, уникальный login, nullable email, имя, роли, `isActive`, даты; миграция и валидаторы.
- Хранить только hash пароля. Реализовать вход по login/password для NextAuth Credentials по контракту задачи 01.
- Закрыть `/api/v1/admin/*` для `ROLE_ADMIN`, пользовательские маршруты — для авторизованных; не доверять роли из данных клиента.
- Исключить hash пароля и чужие данные из сериализации; деактивированный пользователь не может получить новую сессию или пользоваться действующей.
- Подготовить безопасное начальное создание администратора без пароля по умолчанию в коде.

## Готово, когда

- Активный пользователь входит; неверный пароль и деактивированный пользователь получают отказ.
- `ROLE_USER` не вызывает admin API; анонимный запрос не получает защищённые данные.
