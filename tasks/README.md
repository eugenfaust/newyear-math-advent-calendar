## Решения, которые нужно зафиксировать при реализации

- В задаче 01 определить контракт между NextAuth и Symfony API: как передаётся удостоверение пользователя, как защищены мутации и как завершается сессия. Один и тот же контракт должен применяться ко всем пользовательским и административным запросам.
- В задаче 10 принять правило `UNIQUE(user_id, year)` для MVP. Для выбора «текущего календаря» API должен использовать однозначное правило по году; исторические календари сохраняются.
- ТЗ допускает только `answerType=NONE` для MVP: поля будущих типов можно хранить, но их проверку и формы ответов не реализовывать.
- ТЗ упоминает административное закрытие календаря без модели и сценария. В MVP незавершённые дни остаются доступны после 31 декабря; закрытие отложено.
- Снимок при назначении фиксирует соответствие «день → задание». Изменение исходного шаблона не меняет назначенный календарь. Само содержимое `Task` ТЗ не требует копировать в снимок; если потребуется неизменность текста уже назначенных заданий, это отдельное продуктовое решение.

Критические архитектурные правила и полная готовность MVP: разделы 47 и 49 исходного ТЗ.
